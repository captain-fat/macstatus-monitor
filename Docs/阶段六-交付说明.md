## 2. 编译与运行

```bash
cd MacStatusMonitor

./Scripts/build.sh          # 编译（release）
./Scripts/package-app.sh    # 组装 .app + 签名 + zip（可选 dmg）
open "dist/MacStatus Monitor.app"
```

- 工具链：Xcode 15+ / Swift 5.9+（本机为 Xcode 27.2 / Swift 6.4，`swift-tools-version: 6.0`，语言模式 v5）。
- 工程没有 `.xcodeproj`，用 Xcode 打开包即可：`open Package.swift`。
- 在受限环境（CI、沙盒）里 `swift build` 需要 `--disable-sandbox`，`build.sh` 已经带上；
  `TMPDIR` 指向 ASCII 路径，避免编译器在非 ASCII 临时目录下崩溃。

### 常用调试入口

```bash
# 菜单栏安装状态、宽度、Popover、设置窗口、配色联动
"dist/MacStatus Monitor.app/Contents/MacOS/MacStatusMonitor" --self-check

# 无界面输出 1 Hz 数据（验证采集）
"dist/MacStatus Monitor.app/Contents/MacOS/MacStatusMonitor" --dump 10

# 自身 CPU / RSS 长跑
"dist/MacStatus Monitor.app/Contents/MacOS/MacStatusMonitor" --soak 60

# GPU 采集链路分步诊断
"dist/MacStatus Monitor.app/Contents/MacOS/MacStatusMonitor" --gpu-probe 3

# 离屏渲染界面预览（不需要屏幕录制权限）
"dist/MacStatus Monitor.app/Contents/MacOS/MacStatusMonitor" --render-previews /tmp/menubar.png
```

## 4. 签名与公证（对外分发）

当前机器**没有可用的代码签名身份**（`security find-identity -v -p codesigning` 返回 0 个），
所以仓库里的 .app 是 ad-hoc 签名。换到你的签名机器后按下面三步走：

```bash
# 1) 用 Developer ID 签名并打包
CODESIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
  ./Scripts/package-app.sh

# 2) 保存一次公证凭据（app-specific password）
xcrun notarytool store-credentials "msm-notary" \
  --apple-id "you@example.com" --team-id "TEAMID" \
  --password "xxxx-xxxx-xxxx-xxxx"

# 3) 签名 + 公证 + 装订
CODESIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
NOTARY_PROFILE="msm-notary" \
  ./Scripts/package-app.sh
```

验证：

```bash
codesign --verify --deep --strict --verbose=2 "dist/MacStatus Monitor.app"
spctl -a -vvv -t exec "dist/MacStatus Monitor.app"
# 期望：accepted / source=Notarized Developer ID
```

- 公证需要网络与 Apple 账号；`package-app.sh` 在 `NOTARY_PROFILE` 存在时会自动
  `notarytool submit --wait` 并 `stapler staple`；
- DMG 需要完整磁盘映像权限；在受限 shell 里会跳过（zip 仍然生成），
  普通终端重跑一次即可得到 `dist/MacStatusMonitor-1.0.1.dmg`；
- **不要开启 App Sandbox**：GPU 真实值依赖私有 IOReport，本工程按 Developer ID 分发设计。

## 5. 安装与卸载

**安装**：把 `MacStatus Monitor.app` 拖进 `/Applications`，双击运行。
首次运行后菜单栏出现图标；开机启动在设置里勾选。

**开机启动说明**（实测结论）：

- `SMAppService.mainApp` 对 **ad-hoc 签名**的应用同样可用，前提是应用在 `/Applications`；
- 之前出现 `notFound` 的真实原因不是签名，而是 **LaunchServices 里同时注册了两份**
  （`dist/` 和 `/Applications/` 各一份），系统解析到了错误的那一份；
- 现在设置里的开关不再因 `notFound` 被禁用，注册失败会显示系统返回的真实错误；
- 如果以后再遇到 `notFound`：只保留一份应用，或在终端执行
  `lsregister -u "/path/to/duplicate.app"` 注销多余的副本，然后重新勾选。

**卸载**：

```bash
# 退出应用（菜单栏 → 退出），然后：
rm -rf "/Applications/MacStatus Monitor.app"
defaults delete com.captainslow667.MacStatusMonitor
```

若开过机启动，再到「系统设置 → 通用 → 登录项」里移除残留项。

## 6. 已知限制

| # | 限制 | 影响 / 规避 |
|---|---|---|
| 1 | GPU 硬件口径依赖私有 `IOReport` | 无法上架 App Store；系统大版本升级可能改频道名，已做失败降级与 N/A |
| 2 | GPU 读数含系统合成 | 空闲桌面 5%–50% 属正常；与 Activity Monitor 同源口径 |
| 3 | 驱动口径高负载饱和 | 60% 与 80% 真值只差 0.9 个点，仅作兜底 |
| 4 | 仅在 M5 / macOS 27 实测 | M1–M4、macOS 14/15 的频道差异未验证；代码对频道缺失容错 |
| 5 | 1x 非 Retina 屏未实测 | 绘制用整数坐标，1x 下描边可能有半像素感 |
| 6 | warn/critical 压力未端到端触发 | 需要 `sudo memory_pressure -S -l warn -s 10` 手动验一次 |
| 7 | 菜单栏常驻 RSS ~124 MB | 主要是 AppKit 状态栏窗口与合成缓存；采集本身仅 55 MB / 0.13% CPU |
| 8 | 开机启动依赖应用位置与唯一性 | 需在 `/Applications` 且 LaunchServices 中只有一份副本；失败时设置里会显示系统错误 |

## 7. 验收清单（建议按顺序过一遍）

1. 双击启动 → 菜单栏出现两行条 + 彩色外框，数值在 1 秒内出现；
2. 点开 Popover → CPU/GPU/内存三行有数据，无"更新于"行；
3. 右键 → 设置… → 改标签为 C/G、条长 20、关闭 GPU 百分比，菜单栏宽度随之变化；
4. 改内存压力 Normal 颜色 → 外框立即换色，"恢复系统默认"可还原；
5. 开 10 个 `yes` → CPU 条接近满；结束进程后回落；
6. 跑一个 GPU 负载（`Tools/Probes` 的 `probe load 20 100 0`）→ GPU 条上升；
7. 挂 5 分钟，观察 RSS 稳定、无崩溃；
8. （可选）`sudo memory_pressure -S -l warn -s 10` → 外框变黄，结束后变回绿。
